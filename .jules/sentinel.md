## 2024-11-11 - [SSRF Bypass via IPv4-Mapped and IPv4-Compatible IPv6 Addresses]
**Vulnerability:** The SSRF protection logic (`isForbiddenHostname`) incorrectly allowed IPv6 addresses formatted as IPv4-mapped (`::ffff:192.168.1.1`) or IPv4-compatible (`::192.168.1.1`) to bypass local internal IP blocklists. The built-in node `URL` parser converts these to hexadecimal formats like `[::c0a8:101]`, which was not adequately detected by the previous substring blocks like `.startsWith('::ffff:')`. These addresses would then be parsed correctly by `fetch` and make requests to internal IPv4 addresses.
**Learning:** `fetch` and `URL` interfaces in Node.js automatically normalize mixed notation IPv6 addresses. Simple prefix checks (like checking for `::ffff:`) are insufficient because the normalized representation will often be converted to standard hexadecimal representation.
**Prevention:** Explicitly decode the hex representation of IPv4-mapped and IPv4-compatible IPv6 addresses, extract the embedded IPv4 payload, and pass it through the existing robust IPv4 blocking logic. Ensure to properly ignore purely IPv6 addresses that also share the `::` prefix (like loopback `::1` or unspecified `::`) to prevent false positives.
