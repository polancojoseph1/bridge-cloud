## 2024-11-03 - SSRF Vulnerability in Hostname Validation
**Vulnerability:** The SSRF protection in `src/lib/ssrf.ts` was bypassable. Node.js `URL` normalizes IPv4-mapped and compatible IPv6 addresses with dot-decimal notations (e.g., `[::192.168.1.1]`) into hexadecimal formats (e.g., `[::c0a8:101]`). Simple string prefix checks were bypassed by these normalized forms, which `fetch` successfully resolves, leading to potential SSRF on internal networks (e.g., 192.168.0.0/16 or 127.0.0.0/8).
**Learning:** Node.js URL parses IPv6 literal IPs containing embedded IPv4 addresses into standard hex-encoded IPv6 literals. String checks are ineffective when this normalization occurs. We need to explicitly check and reconstruct the underlying IPv4 address from the normalized hexadecimal form and pass it into the existing `parseIPv4` blocklist.
**Prevention:** When building custom SSRF validation functions, always account for URL normalization of IPv4-mapped and compatible IPv6 formats into hex, and validate the resulting decoded internal IPv4 addresses. Use well-tested libraries for SSRF mitigation instead of custom code whenever possible.
