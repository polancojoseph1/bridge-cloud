## 2025-02-14 - Fix SSRF via Node.js URL normalisation bypass
**Vulnerability:** The proxy server had an SSRF vulnerability where IPv4 addresses provided in an IPv4-mapped (e.g. `[::ffff:192.168.1.1]`) or IPv4-compatible (e.g. `[::192.168.1.1]`) IPv6 format could bypass the host blocklist. Node's `new URL()` resolves these embedded IPv4 addresses into standard hex-packed IP formats like `[::ffff:c0a8:101]` and `[::c0a8:101]` which passed the IPv6 prefix block.
**Learning:** `new URL()` actively normalizes dot-decimal IPv4 representation within IPv6 mappings into hexadecimal strings, which easily bypasses naive prefix checks (`.startsWith('::ffff:')` against the IPv4 part) or IPv4 octet extraction logic. Furthermore, pure loopback `::1` or unspecified `::` can mistakenly be parsed as IPv4 `0.0.0.1` and `0.0.0.0` respectively and un-blocked if matching logic isn't careful.
**Prevention:** Check normalized parsed hostnames for embedded IPv4 addresses (using accurate hex string parsing for mappings) and explicitly block plain loopback/unspecified IPv6 IPs to avoid erroneous parsing.
