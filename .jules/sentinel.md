## $(date +%Y-%m-%d) - Prevent SSRF Bypass via Trailing Dot and IPv6 Parsing FQDN
**Vulnerability:** The SSRF validation logic in `isForbiddenHostname` fails to strip trailing dots before checking domains (e.g., `127.0.0.1.`), which allows users to bypass literal IP or domain blocklists, as Node's `dns.lookup` incorrectly fails (ENOTFOUND) but `fetch` resolves successfully. Also, IPv6 normalization was missing, causing `::ffff:127.0.0.1` and `::127.0.0.1` bypasses depending on exact matching rather than normalized parsing.
**Learning:** Node.js's built-in `URL` preserves trailing dots in FQDNs. Custom SSRF filters that rely on exact matching or strict parsing (e.g. `split('.')`) must first sanitize these structural anomalies by removing trailing dots and using `new URL('http://['+ip+']').hostname` to properly normalize IPv6 formats.
**Prevention:** Always sanitize trailing dots (`.replace(/\.$/, '')`) from parsed hostnames and utilize the built-in `URL` module to normalize IPv6 formatting before applying any SSRF blocking validation.
