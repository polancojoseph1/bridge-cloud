## 2025-02-14 - SSRF bypass via IPv4-compatible IPv6 hex normalization
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) bypasses. Node.js `URL` normalizes IPv4-mapped and IPv4-compatible IPv6 addresses with dot-decimal notations (e.g., `[::192.168.1.1]`) into hexadecimal formats (e.g., `[::c0a8:101]`). The existing string prefix check `.startsWith('::ffff:')` and strict exact matches failed to catch these normalized forms, allowing requests to internal IPv4 addresses through `fetch`.
**Learning:** Checking for string prefixes (`::ffff:`) or matching generic patterns isn't sufficient for blocking IPv4 representations within IPv6 space because standard URL normalizations convert decimal formats into valid hex parts (e.g. `[::c0a8:101]`).
**Prevention:** Explicitly parse and extract the hex portion of IPv4-mapped/compatible IPv6 addresses (`::ffff:hex` and `::hex`), convert them back to integers/octets, and ensure the embedded IPv4 payload is passed through the same internal blocklist rules as standard IPv4 addresses. Ensure exclusions exist for valid small pure IPv6 addresses like `::1` or `::` that shouldn't be parsed into IPv4 space.
