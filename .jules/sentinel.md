## 2024-05-18 - SSRF bypass in IPv6 validation due to Node.js URL normalization
**Vulnerability:** The application was correctly blocking IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`) but the string matching for other IPv6 addresses was weak. When attempting to fix this by using `new URL('http://['+ip+']')` to normalize the IP, a secondary vulnerability was introduced: Node's URL normalizer converts `::ffff:127.0.0.1` into `::ffff:7f00:1`. This bypassed naive dot-decimal parsing (`split('.')`), allowing attackers to access restricted internal networks using mapped addresses.
**Learning:** You cannot blindly mix standard IPv6 normalization with dot-decimal IPv4-mapped IPv6 parsing. Node.js `URL` normalizes IPv4-mapped addresses to standard hex representation, dropping the dot-decimal format. Attempting to parse the resulting string with `parseInt(..., 16)` on standard dot-decimal parts leads to incorrect evaluations and SSRF bypasses.
**Prevention:** When extracting the embedded IPv4 address from an IPv4-mapped IPv6 address that has been normalized via `URL`, you must parse the final two 16-bit hex segments, not dot-decimal octets. E.g., `['', '', 'ffff', '7f00', '1']` -> `parseInt('7f00', 16)` and `parseInt('1', 16)`, which are then shifted to reconstruct the IPv4 string for recursive validation.
