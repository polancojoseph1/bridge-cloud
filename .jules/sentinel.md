## 2024-03-24 - SSRF Bypass via IPv4-Compatible IPv6 Addresses
**Vulnerability:** Node.js's `URL` constructor parses IPv4-compatible IPv6 addresses (like `::127.0.0.1`) and automatically strips the dot-decimal segment, converting the hostname to a standard IPv6 hex representation (like `::7f00:1`). An SSRF validation filter that only string-matches IPv4 mapped (e.g. `::ffff:`) or standard IPv4 patterns fails to block these bypasses, allowing requests to internal network services.
**Learning:** URL normalization logic (like parsing by `new URL()`) often modifies IP representations in unexpected ways before validation logic receives them. Attackers use this to evade string-based or regex-based security checks.
**Prevention:** Always perform SSRF verification on the exact hostname parsed by `new URL()`, and ensure parsing logic explicitly un-maps both IPv4-mapped and IPv4-compatible IPv6 formats to re-validate the underlying encapsulated IPv4 address against blocklists.
